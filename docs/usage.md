# 使用指南

## 首次配置与组件安装

在工作总览点击「快速配置」，按检测环境、选择模型、连接 QQ、检查并启动四步操作。随时可返回上一步或切换到全部连接设置；两个入口共用草稿，最后统一保存。默认工作区与配置在缺失时初始化，已有文件不覆盖。

首页引导只在首次配置未完成时显示。检查通过并保存，或 QQ 与模型成功连接后会记住完成状态；后续启动、停止和短暂离线都不会重新显示。需要调整时，可从「连接与运行」手动打开「快速配置」。

| 缺少的组件 | 去哪里准备 | 回到控制台后做什么 |
| --- | --- | --- |
| DSH | [DeepSeek Harness 官方下载](https://deepseek.com/harness/) | 自动检测，或选择安装目录中的 `dsh.cmd`；已有模型配置或账号须先在 DSH 配置或登录 |
| QQ | [QQ Windows 官方下载](https://im.qq.com/pcqq/) | 本机模式选择 QQ.exe 所在目录；外部服务模式无需本机 QQ |
| NapCat | [NapCat 官方安装说明](https://napneko.github.io/guide/boot/Shell) | 先按说明启动、登录并配置网络，再选择连接已有服务；本机受管模式见下一节 |

自动检测只检查 PATH、常见安装位置和正在运行的 QQ / DSH 的程序路径，不执行安装器、不下载组件、不扫描整个磁盘。已找到的路径只填入未修改的空白或默认项，保存前可以继续修改。

首次使用模型时建议选择「本项目 API Key」，填写密钥与服务支持的模型 ID；默认地址为 DeepSeek Messages 接口。选择沿用 DSH 或账号登录只代表复用凭据，基础检查不会验证真实模型调用是否成功。项目 Key 的「测试连接」会实际请求模型并可能收费，由用户自行点击。

QQ 接入方式保存在 `BOT_ONEBOT_MODE`，仅控制桌面端的 QQ 进程管理：

| 方式 | 值 | 行为 |
| --- | --- | --- |
| 自动连接 | `auto`（默认） | 优先复用可连接的 OneBot，否则启动已部署的本机 NapCat |
| 工作台启动本机 NapCat | `managed` | 使用本机 QQ 与 NapCat 运行组件 |
| 连接已有服务 | `external` | 不启动本机 NapCat，外部服务暂时离线也不会误启动本机 QQ |

NapCat 的 HTTP 服务与正向 WebSocket 服务通常分别使用 `3000`、`3001`。两端的 `access_token` 须一致；不要把反向 WebSocket 地址填入本项目。QQ 号默认自动识别，管理员 QQ 可稍后到机器人设置中填写。

「检查当前配置」检查尚未保存的输入，不改写文件、不发送消息、不请求对话模型。已有服务会检查 HTTP 鉴权和 WebSocket 握手；由工作台启动的本机服务尚未运行时，会明确说明需在启动后完成登录。本机模式需要的文件缺失会阻止通过；外部服务模式则将其标为「可跳过」。失败项可点击「去设置」定位，修改输入后必须重新检查。

检查通过后点击「保存并启动」，保存失败不会启动。基础检查通过不等于 QQ 已登录或模型已就绪，需等待工作总览两项状态连接成功，再发私聊或 @ 机器人验证。媒体、搜索、主动行为和高级参数可以之后逐项开启。

## QQ 与 NapCat

可连接外部 OneBot，也可由工作台管理本机 NapCat。OneBot 11 推荐设置 HTTP `http://127.0.0.1:3000`、正向 WebSocket `ws://127.0.0.1:3001`，配置令牌并选择消息段数组格式；项目连接设置须保持一致。

本机 Node 模式需要预先部署官方 NapCat Shell 到 `napcat/shell/`，并将官方 Node 运行适配库 `QQNT.dll` 放入 `napcat/node-runtime/QQNT.dll`。这个库与 QQ 安装目录的同名文件用途不同，不能互换。在「连接与运行」选择 QQ 安装目录与 DSH 启动文件，首次启动按 NapCat 日志完成扫码。

`scripts/napcat-node.mjs` 从 `BOT_QQ_DIR` 读取 QQ 版本，复制所需组件到独立 `node-runtime/`，不修改系统 QQ。首次部署复用 Shell 中的账号配置，后续以 `node-runtime/config/` 为准。手动运行 `npm run napcat` 的进程需在原终端停止。

新建和恢复 ACP 会话时，桥接自动挂载名为 `qq` 的 MCP。若旧 DSH Profile 中手动添加过同名 QQ MCP，需移除重复项；其他已挂载工具继续独立管理。

## 设置、人设与参与

「机器人设置」管理行为开关、参与方式、权限、额度与上下文；「连接与运行」管理地址、密钥、模型与存储位置。两页按各自范围保存；高级环境文本与普通表单互斥编辑，切换前需保存草稿。`bot.config.json` 中的显式值优先，缺失项才使用 `.env` 默认值。

「人设与记忆」支持命名人设库、全局人设、群友记忆、工作区记忆和群内用语。全局人设保存到 `BOT_WORKSPACE/AGENTS.md`，新会话读取；人设库在 `.whale/personas.json`，单条最多 10000 字。工作区记忆管理 `memory/` 下的 Markdown 与文本文件，支持子目录和外部修改冲突检查。

群友记忆与群内用语统一在「人设与记忆」查看和编辑。「QQ 活动」按日常互动、自主活动、运行记录分组，记录详情只显示与当前类型相关的操作。今日用量集中在「机器人设置 → 额度与节奏」，按已保存的额度统计。

「QQ 活动 → 会话人设与参与」可复制某个人设为会话专属内容，也可覆盖全局参与方式。会话保存独立副本，后来修改或删除库内人设不会同步覆盖。

| 参与方式 | `social.responseMode` | 普通群消息 |
| --- | --- | --- |
| 沿用群聊开关 | `legacy` | 使用 `chat.group.requireMention`，开启时等待直接对话 |
| 仅直接对话 | `mention` | 不因普通旁聊触发 |
| 直接对话和关键词 | `keywords` | 关键词命中时触发 |
| 关键词和概率参与 | `probability` | 关键词命中或概率判断通过时触发 |
| 参与全部消息 | `all` | 普通消息也触发，仍受冷却和队列约束 |

@、配置称呼或 QQ 昵称、前缀、引用机器人消息及有效追问算直接对话。默认追问窗口为 90 秒；引用第三方或 @ 其他人不自动当作追问。直接对话不被普通旁聊冷却静默丢弃，仍受容量约束。

同会话串行，默认最多并发处理 4 个会话；每会话容量 5、全局容量 50，包含正在处理的消息。超量消息不进入模型；忙碌提示限频。管理员审批回复先于普通队列处理。

群背景默认每群保留最近 24 小时最多 80 条，最多 100 个群，单条最多 2000 字；在轮次开始时选取背景，不混入排队期间更晚的消息。`contextLines=0` 关闭附加群背景，不清空 ACP 已有历史。

## 记忆整理与群内用语

开启「功能开关」中的记忆整理或用语学习后，还需在允许列表指定 `group:群号` / `private:QQ号`。空列表不分析任何会话。项目 Key 模式复用 Messages 接口；Profile 或账号模式须配置独立分析密钥。独立服务地址属于其他服务商时，必须填写其对应密钥。

| 环境变量 | 用途 |
| --- | --- |
| `BOT_LEARNING_BASE_URL` | 独立 Messages 地址；留空复用项目地址 |
| `BOT_LEARNING_API_KEY` | 独立分析密钥；项目 Key 模式可复用项目密钥 |
| `BOT_LEARNING_MODEL` | 分析模型；留空使用对话模型名称 |

默认累计 40 条新消息、同会话相隔 60 分钟、空闲 5 分钟且没有普通消息排队时分析；全局并发 1，每日最多 6 次，上海零点重置。手动「整理此会话」跳过消息数量与空闲条件，仍校验会话许可、开关及共享额度。分析不挂载 QQ、工作区或浏览器工具。

结构化提案通过消息、发送者、证据与版本核验后写入。同文记忆合并来源；矛盾事实等待人工确认。管理员修改会锁定，保留最近 10 次内容版本。删除留下抑制指纹，旧消息不能立即重新生成相同记录；撤回来源会停用依赖该来源的未锁定内容。格式校验不能保证模型语义判断正确，重要事实应人工复核。

记忆按当前发言者、相关词与时效召回，默认最多 12 条、1800 字，完整条目计入预算；冲突、过期、撤销、屏蔽或跨会话记录不自动注入。

用语按来源群隔离，自动候选至少需 3 条不同消息、2 位发送者支持，确认后才生效。支持修改、确认、停用、删除与恢复版本。默认每轮最多 4 条、400 字，仅召回相关有效词条；停止学习后仍可使用已确认词条，也可单独关闭使用。

分析失败或中断保留额度与处理游标，不自动重试同一批消息。QQ 活动的后台学习记录显示实际状态与服务返回的用量，未返回时显示未知。

## 搜索与网页正文

「功能开关 → 联网核实」选择自定义适配、Tavily 或实验性 Bing，并可指定一个备用提供方。Tavily 使用 `BOT_TAVILY_API_KEY`；适配使用 `BOT_SEARCH_URL` / `BOT_SEARCH_API_KEY`。

`qq_search` 返回标题、链接、摘要、抓取时间和来源编号。适配服务接收 `POST {query, images}`，返回 `{"results":[{"title":"标题","url":"https://example.com","snippet":"摘要"}]}`；图片结果可另含 `imageUrl`。Bing HTML 解析可能受页面变化或网络影响，不支持图片搜索。

`qq_web_read` 接受公开 URL 或本会话的 `source_id`，后者十分钟有效。只提取静态 HTML / 纯文本，不执行脚本、不加载资源，不支持需登录或动态渲染的正文。默认每轮搜索最多 2 次、正文读取最多 3 次，分页也计次；每页最多 8000 字，使用 `nextOffset` 继续。

搜索缓存按会话、查询、图片选项和提供方隔离，默认十分钟，可用 `refresh` 刷新；磁盘最多 200 项，清理超过一小时的项。网页下载限制公网地址、重定向与体积，不携带搜索密钥。

这些开关和预算管理本项目 QQ 联网工具，DSH 自带或另外挂载的工具独立管理。旧截图字段仅兼容保存，没有内置浏览器截图能力。

## 上下文与工具预算

群背景默认最多 3000 字，当前问题完整保留；记忆和用语分别计入自己的预算。ACP 历史、会话人设和兴趣仍构成输入，局部字数预算不代表完整模型 token 上限。

默认沿用 DSH 压缩。可开启高占用时更换会话，默认 70% 提醒、85% 换代，下一轮检查 DSH 上报的占用比例。新会话和映射保存成功后才切换，交接有限的近期真实记录；失败保留旧映射。换代不删除消息、记忆、提醒和兴趣，不重做已执行动作。

可选按功能开关与依赖提供 QQ 工具，清单变化时下一轮更换会话。所有 QQ 入口共享本轮次数，默认最多 80 次；执行处继续检查最新权限。上下文占用来自 ACP `usage_update`，不是计费用量；费用相关记录只使用协议明确返回的数据。

## 表情、媒体与文件

收到的图片先看图分析，收藏写入 QQ 账号并按 MD5 回读核验，结果未知不记作成功。支持同步账号收藏、含义和场景检索、预览与发送；关闭独立视觉模型时可把图片交给支持视觉的 DSH 会话。后台安静挑选表情需要独立视觉能力及相关开关。

| 能力 | 条件 |
| --- | --- |
| 图片理解 | 支持视觉的 DSH，或独立视觉模型 |
| 图片与表情发送 | 在线 OneBot；网络图片先下载到媒体库 |
| 语音识别 / 合成 | 兼容媒体服务与对应模型，不可把 TTS 模型用于转写 |
| 视频理解 | FFmpeg 抽帧，加 DSH 视觉或独立视觉模型 |
| 文本文件阅读与生成 | 受控下载和媒体库；Markdown、文本、CSV、JSON 可直接处理 |
| PDF、Word 等二进制正文 | 交给 DSH 已配置的文档能力 |

在「连接与运行 → 媒体服务」配置地址、密钥、模型、音色与 FFmpeg。通用服务使用 `chat/completions`、`audio/transcriptions`、`audio/speech`。环境变量为 `BOT_MEDIA_BASE_URL`、`BOT_MEDIA_API_KEY`、`BOT_FFMPEG_BIN`；模型名称可热更新，服务连接修改后需重启。

千问AI平台的 `qwen-audio-3.x-tts-flash` / `qwen-audio-3.x-tts-plus` 支持原生 SSE 合成。地址填写 `https://maas.qianwenaiapi.com/compatible-mode/v1`，国际站为 `https://maas.qwencloudapi.com/compatible-mode/v1`；程序调用同服务的原生 TTS 接口，直接读取 MP3 字节。声音填写模型支持的实际 ID，例如 `longanlingxi`，不能用中文显示名。千问原生 ASR 尚未适配，转写仍需兼容服务。

网络图片直链失败时，可对已记录 QQ 消息使用协议 `get_image` 获取缓存或 Base64；本机缓存需通过格式与大小校验。工具任意传入的本地路径、内网 URL 不享有该例外。其他本地媒体默认仅允许媒体库、工作区 `output/` 和 `BOT_MEDIA_IMPORT_DIRS`（多个绝对目录用 `|` 分隔）。媒体库默认 512 MiB，不自动删除仍在使用的表情。

## 主动行为、提醒与空间

后台主动总开关 `social.proactiveEnabled` 默认关闭。开启后从实际消息、兴趣和未完想法中挑选候选，每次至多处理一条，没有合适内容可以保持安静。同会话忙碌时延后，对方未回应时暂停追问；过期想法不补发。安静时段暂停后台聊天、收藏与创作，约定的提醒仍按时间执行。

QQ 活动支持推迟或取消想法、编辑或删除兴趣、查看行动摘要。空间创作使用独立会话，只注入公开创作主题与自己的发布摘要，不读取私聊和群记录；自主配图只允许经过校验的公网图片。

| 额度 | 默认行为 |
| --- | --- |
| 主动消息 | 每日 5 条；普通回复不占主动额度，但受每日动作总额约束 |
| 主动群消息 | 默认关闭；启用后每群每日 1 条，同时受总额度约束 |
| 名片点赞 | 每日 20 次，按实际请求次数扣除 |
| 空间发布 | 默认关闭；启用后默认每日 1 条，发布前确认 |
| 后台判断 / 新增收藏 | 默认每日 24 次判断 / 3 张收藏，还需主动与能力开关 |

0 表示禁止对应动作。提醒持久化，支持一次或周期任务、查询、取消及重启恢复。远端结果未知保留预扣与核对记录，避免重复发送。QQ 动作审批与空间确认可合并为一次实际内容确认；命令执行和文件修改另行审批。

空间发布需要协议 `send_qzone_msg` 扩展，不依赖浏览或评论适配。空间动态与评论必须配置 `BOT_QZONE_ADAPTER_URL` / `BOT_QZONE_ADAPTER_TOKEN`：动态请求 `{"action":"feed","user_id":123456,"limit":10}`，返回 `{"posts":[{"id":"真实编号","text":"正文"}]}`；评论请求 `{"action":"comment","post_id":"真实编号","text":"评论","reply_id":"可选编号"}`。只能评论当前进程实际取得的动态。

## 数据、恢复与排障

会话、额度、群记录、社交存档和媒体默认位于 `data/`，可由对应环境变量调整。数据绑定 QQ 账号，换账号应使用独立目录；同一数据文件只由一个桥接实例写入。损坏数据会保留原文件并报告错误。

社交存档版本 2 首次读取版本 1 时，先生成带摘要的 `social.json.v1-*.bak`，保留旧记忆原文和 ID，再原子迁移。回退旧程序前必须停止桥接并恢复对应旧版备份；旧程序不能直接读取新版数据。备份含个人聊天，须留在本机。

重置模型会话不会删除长期记忆与消息存档。屏蔽过滤后续输入与查询，但不能抹除已有 ACP 历史；需要时重置该会话。记忆内容统一在「人设与记忆」查看、编辑和删除。

工作日志保留最近 1500 行，支持搜索、暂停滚动和导出；脱敏日志位于 `data/desktop/console.log`，超过 2 MB 轮换。模型断开、QQ 离线、媒体不可用和后台学习缺条件会分别显示。

退出时保存会话与额度，取消未完成轮次并清理受管 DSH。托盘不可用或 DSH 报权限错误时，先查看启动诊断；退出工作台后重新构建 EXE，可恢复普通用户完整性级别。不要同时从桌面和终端启动同一桥接。

自动测试只验证受控协议与服务链路。真实 QQ 媒体、申请、空间、搜索提供方可达性和模型提取质量仍需实际环境验证。协议能力以部署版本为准，参考 [NapCat API](https://napneko.github.io/onebot/api)。
