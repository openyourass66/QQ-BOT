# 小鲸工作台正式发行改造方案（精简版）

更新日期：2026-10-28。项目源码版本：`0.2.0`。最近完整验证对应的代码检查点：`cbdd91e`。工作区另含尚未提交的开发代码，见第 2 节。

本版按已确认的要求重新编制：**仍面向普通用户正式发行，保留原发布门槛，只缩减首发功能与实现范围。** 现有机器人能力继续保留；开发重点从继续扩展架构，转为完成发行、必要维护和实际验收。

本文件是后续实施依据。[完整原方案](product-readiness-plan-full-2026-10-28.md)保留历史设计、原工作包和调研依据；[实施进展](implementation-status.md)保留已做事项和实际验证。原方案中的未完成项按本版重新划分为首发必做和后续迭代，不再全部作为首发开发任务。

## 1. 交付目标与边界

交付 Windows 10/11 x64 的正式版本，支持单机、单主人、单 QQ 账号、一个数据实例。用户可以通过图形界面完成安装、组件准备、模型配置、QQ 扫码、联系人范围选择和首次聊天，无需安装 Git、npm、TypeScript 或自行编译。

交付物仍包括完整 ZIP、用户级安装程序、固定组件和许可清单、中文使用说明、备份恢复与升级回退入口，以及第 7 节要求的验收记录。先形成可测试候选包，再制作正式版本；候选包的试用不代表已经满足发布门槛。

用户提供 QQ 账号、模型凭据、联网条件和登录验证。受管组件沿用现有固定来源、版本与校验；不新增未经验证的组件或模型服务。现有外部 OneBot、自定义模型和便携/自定义数据目录保留高级入口，在声明支持的组合上验收。

以下五包覆盖剩余交付；合并工作包只改变排期与管理方式，不减少对应的验证。已通过的基础实现直接复用，只有缺陷或新边界需要修改。

| 工作包 | 要完成的具体结果 | 完成条件 |
| --- | --- | --- |
| V1 候选包与首次使用 | 从明确代码检查点构建完整 ZIP，包含必需脚本、依赖、运行库和资源；跑通组件准备、模型、QQ、联系人选择和聊天 | 从包本身启动，不依赖开发目录；本机独立数据实例完成真实收发，缺配置/缺组件/登录失败均有可继续的提示 |
| V2 运行边界收尾 | 修复学习游标、冷却、睡眠/时钟变化、取消及失败退让问题；验证队列/载荷上限；完成停机媒体清理 | 已声明能力的重启/取消/未知结果不重复执行；清理保护收藏、任务、未知动作、用户文件和被替换路径；管理查询与停止保持可响应 |

### 4.1 执行顺序与停止加范围的条件

1. 先完成 V1，尽早形成明确版本的候选包；当前未提交代码须单独完成验证后纳入，或保留在开发现场并从已验证提交构建。
2. 完成 V2、V3、V4 的首发缺口，每次只解决一个可以独立验收的问题，不顺带新增适配器、界面体系或架构层。
3. 冻结候选进入 V5。冻结后只修复阻塞发布的缺陷；一般体验优化和后置功能进入后续清单。
4. 每个工作包达到表中完成条件即关闭。追加任务必须指出对应的发布门槛或具体缺陷，不能仅以“更完善”为由继续扩大范围。

## 5. 简化实现的具体约定

### 5.1 停机维护

备份、恢复与清理共用实例资源锁。先停止桥接、受管 QQ 和数据库写入，再操作选定数据实例；已有外部 OneBot 不由本程序误结束。运行实例占用资源时，维护明确拒绝并提示停止；维护未收尾前也不能启动同一份数据。

备份至少包含四库、配置、人设/工作区记忆、必要媒体清单及对应文件，并记录格式/应用/数据版本、摘要和来源。私有备份中的凭据材料保持现有安全存储格式，不导出明文；同 Windows 用户可以按受支持方式恢复，换用户/机器时提示重新输入凭据和扫码。私有备份与可分享诊断包明确分开，QQ 登录资料不进入诊断包。

恢复先校验版本、摘要、完整性、容量和路径，建立当前恢复点后才切换。失败保留原数据和备份；已产生新数据时不能自动恢复旧快照覆盖它。升级前恢复点是必做项，日常自动备份调度后置。

媒体清理先采用停机手动入口，保留默认三十天的无引用缓存，允许用户明确调整。两库引用必须完整且可核验；文件受管名称、实际路径、大小、内容、占用和引用状态不确定时保留。收藏、待发送/待执行任务和未知动作依赖不删除。保留现有总容量、文件数和待写上限；达到上限给出清理/调整入口，禁止静默移除受保护文件腾空间。

### 5.2 手动升级与修复

首发只有一条维护路径：用户获取完整发行包并在本机发起，安装/更新助手负责验证和操作。手动获取不减少可信来源、版本兼容、摘要/签名、空间检查和程序/数据配套回退要求。程序目录与用户数据继续分离，不采用覆盖用户数据目录的安装方式。

沿用内置可信公钥验证发行清单签名，再核对包摘要；首次正式发行至少完成可信清单验证和来源说明，不能用 HTTPS 或自行计算摘要代替发布者签名。EXE 的发布者签名按原方案独立配置，不因后置在线下载而取消清单验证。

保留启动前和切换后的检查；新程序尚未开放业务时失败，可恢复相配的程序与数据。新版本已产生数据后，转入明确的人工核对/导出流程，不能自动还原旧备份。组件修复继续使用固定清单和独立版本目录，不扩展通用下载/执行入口。

### 5.3 界面与可选能力

沿用现有工作总览、快速配置、设置、活动、诊断和托盘。新增维护操作放入现有页面或简单对话框；显示过程、取消、结果与主要修复动作。保留分页/懒加载与管理响应上限要求，修复实测卡顿和无界响应；不把全面改版作为验收前置。

账号管理通过真实主人消息与现有内容绑定确认执行，角色、目标、当前账号、范围、取消和额度仍在实际提交前复验。现有人设、记忆、自主聊天/收藏/空间功能保留开关和预算；新实例的有限范围与基础聊天默认值继续使用。

所有宣称支持的媒体、空间和原生联网组合分别真实验收。缺依赖或验证失败的组合显示明确限制，不能只验证基础聊天就宣称所有功能可用。增加新的支持组合另行排期。

## 6. 验证标准保持不变

### 6.1 必要验证

- 类型检查、全量隔离回归，以及权限、仓储、动作、取消和容量的针对性检查；测试数量只记录事实，不折算完成比例。
- 真正的多进程抢锁/宿主退出、迁移中断/磁盘满/损坏/过新版本、发送后确认丢失和进程树回收。
- 从新包验证组件准备、受管登录、真实消息及所声明支持的图像/语音/空间/联网组合。
- 干净 Windows 10/11 x64、普通用户、无开发依赖；覆盖中文/空格/长路径、只读安装位置、100%/125%/150% 缩放及键盘操作。
- 托盘实际恢复和退出、配置草稿、错误修复、备份/恢复/诊断、安装/升级/配对回退演练。程序化托盘调用不能替代物理交互验收。
- 固定依赖 CI 必须实际运行并保留产物记录；不能以配置文件存在代替通过。

### 6.2 性能与容量目标

下表原样沿用原方案的验收值和口径。

| 指标 | 拟定验收值 | 统计范围 |
| --- | --- | --- |
| 首次窗口可操作 | 冷启动 ≤ 5 秒 | 排除组件下载、系统安装和 QQ 登录 |
| 已配置实例本地就绪 | ≤ 15 秒 | 5 万条存档；外部登录/服务不可用时单列等待原因 |
| 归档持久化延迟 | P95 ≤ 100 ms | 5 万条存档，20 会话合计 10 条/秒，持续 30 分钟 |
| 数据库增量写入 | P95 ≤ 30 ms | 在上述负载下，单独统计 Worker 内执行与提交 |
| 突发处理 | 50 条/秒、60 秒内内存与队列受限 | 允许按既定规则拒绝旁聊，记录接纳/拒绝/落盘数量 |
| 主事件循环延迟 | P99 ≤ 100 ms | 稳态测量，独立报告下载/迁移等特殊阶段 |
| 管理页面交互 | 常用查询/控制 P95 ≤ 200 ms | 首屏分页 100 条，排除外部协议网络等待 |
| 桥接进程常驻内存 | 稳态 ≤ 256 MiB，峰值 ≤ 384 MiB | 5 万条数据；DSH、NapCat、UI、Worker 分进程/线程另列 |
| 数据扩展趋势 | 同口径 5 万条相对 1 万条的增量写入 P95 不超过 2 倍 | 排除启动迁移与批量维护，不全量加载历史 |
| 容量上限行为 | 无无限排队、无假成功、无未计数丢弃 | 混合普通消息、大消息、媒体和后台任务 |

桥接 RSS 包含 Worker；DSH、NapCat 和界面分别报告。沿用固定种子、二十会话、1 万/5 万/10 万条三档数据，各档预热后至少三轮、每轮三十分钟混合负载，记录 P50/P95/P99、吞吐、事件循环、RSS、队列、磁盘和 WAL，以及实际组件/硬件与代码版本。短串行基准不能替代该报告。目标未达先定位修复，不删除失败样本或自行降低支持规模。

### 6.3 稳定性与新用户

候选版先进行 **72 小时混合负载运行，再完成 7 日真实小规模使用观察**。固定输入与清理条件下观察静置基线，沿用七日末内存增长不超过 15% 的目标，记录重启、缓存变化和异常。影响运行行为的修复重新开始对应观察；文档工作可交叠。

至少五位未参与开发的用户独立完成首次设置，至少四位无需开发者远程代操作即可成功。组件、账号和密钥已准备且不含下载/验证等待时，向导与首轮聊天目标十分钟内完成；实际下载和验证等待单独记录。所有阻塞问题修复后复测。真实负载使用独立测试账号和数据，不故意制造批量外部动作。

## 8. 排期、资源与后续迭代

本版不沿用原整套改造的人日估算。先完成 V1 候选包及复验，依据暴露的实际缺陷和 V2–V4 的明确缺口安排开发；每包记录实现、验证、剩余问题和版本。正式发行仍受连续运行观察及测试资源约束，缩减开发功能不会缩短既定观察期。

当前可用设备仍只有本机，干净 Windows 10/11 环境和五位试用者尚未落实；这些是待补齐的验收资源，不能以缺少资源免除门槛。新包与真实收发使用独立实例、现有已授权的测试范围，具体账号和凭据不进入公开文档。

后续迭代再讨论在线清理、在线/定时备份、自动更新平台、完整维护中心、账号管理专页、进一步架构拆分、网页控制台与云端/Linux 发行。已有代码与数据不因范围调整删除；未完成项明确标为后置，不标记为已验收。

完成 V1–V5 并满足 G01–G06 后，本轮改造结束；以后的新增能力另立范围，不继续延长本轮交付。
