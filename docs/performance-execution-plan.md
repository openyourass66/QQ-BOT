# 本机性能检查与长时负载执行方案

更新日期：2026-10-30。依据[精简方案第 6.2 节](product-readiness-plan.md#62-性能与容量目标)，验收口径不降低。本文件只定义本机可执行部分；未执行的项目保持待办，短基准不计作达标。

## 当前状态

- 已有 `npm run benchmark:store` 诊断基准（合成数据、串行存储、1 千/1 万/5 万条），结果标记 `diagnosticOnly`，不能替代混合负载验收。
- 正式混合负载、突发、队列、RSS/WAL 采样和 72 小时运行尚未执行。

## 执行环境记录

每次执行前记录并在报告中保留：Windows 版本与补丁、CPU/核数、内存、磁盘类型与可用空间、应用与 Node 版本、固定组件版本、数据目录路径、是否启用真实 FFmpeg、测试账号与模型服务是否参与。

## 数据与负载

| 项目 | 约定 |
| --- | --- |
| 数据档位 | 1 万、5 万、10 万条；固定种子生成，三档分别独立实例 |
| 会话规模 | 20 个会话，普通旁聊与直接对话按既定准入比例混合 |
| 稳态负载 | 合计 10 条/秒，持续 30 分钟；每档预热后至少三轮 |
| 突发 | 50 条/秒持续 60 秒，记录接纳、拒绝、落盘数量 |
| 后台任务 | 保留自主/学习/提醒的真实开关配置，记录任务领取与取消 |
| 媒体 | 声明支持的图像/语音/视频组合单独成组，不与其他指标混合统计 |

## 采样与产出

- 每轮记录：归档 P50/P95/P99、数据库 Worker 写入 P50/P95/P99、主事件循环 P99 与最大值、吞吐、队列深度、进程 RSS（桥接、DSH、NapCat、UI 分列）、磁盘写入与 WAL 大小、失败与拒绝计数。
- 首次窗口冷启动（排除下载/安装/扫码）与已配置实例本地就绪时间单独测量。
- 管理页面常用查询与控制 P95 单独测量，排除外部协议网络等待。
- 产出 JSON 或 Markdown 报告，保存到 `release/cache/`（不提交），并在验收记录中写明确路径、代码版本和实际硬件。
- 失败样本必须保留；目标未达先定位修复，不删除样本或降低支持规模。

## 判定

| 指标 | 验收值 |
| --- | --- |
| 首次窗口可操作 | 冷启动 ≤ 5 秒 |
| 已配置实例本地就绪 | ≤ 15 秒（5 万条） |
| 归档持久化 P95 | ≤ 100 ms |
| 数据库增量写入 P95 | ≤ 30 ms |
| 主事件循环 P99 | ≤ 100 ms |
| 管理页面 P95 | ≤ 200 ms |
| 桥接常驻内存 | 稳态 ≤ 256 MiB，峰值 ≤ 384 MiB |
| 5 万相对 1 万的增量写入 P95 | ≤ 2 倍 |
| 容量行为 | 无无限排队、无假成功、无未计数丢弃 |
| 长时稳定 | 72 小时混合负载后 7 日观察，内存增长 ≤ 15% |

## 未完成条件

干净 Windows 10/11、独立测试账号、真实模型配额和连续 72 小时运行窗口尚未落实。条件具备前，本方案只完成诊断基准与脚本核对，不将任何档位标为正式性能通过。
