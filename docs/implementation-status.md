## 实现说明

### 第二批：运行目录与账号权限

目录与入口的完整约定见[运行布局说明](runtime-layout.md)。源码保留原数据位置，发行布局默认使用用户数据目录；便携和自定义位置必须显式选择。桌面、配置管理、诊断、命令行、NapCat、日志和首次配置完成标记已接入。首次初始化保留已有配置与人设，写入失败不会换一份空目录继续运行。原生窗口复用 JavaScript 路径解析，按数据目录建立单实例标识，支持路径空格和目录联接。

桌面配置文件优先级已统一：诊断、配置编辑器与实际启动子进程使用同一份保存内容，避免环境中遗留的值覆盖刚保存的配置。DSH 带目录的相对启动路径及数据路径先转为绝对路径。

账号管理采用确认后的产品规则：只有本机配置的机器人主人发起的真实消息可以调用 `qq_set_profile`、`qq_set_avatar`、`qq_set_group_card`、`qq_handle_request`。消息身份由桥接记录，通知、提醒、自主任务和无来源上下文不获得主人身份；自主模式与一次审批都不能提升普通群友权限。确认后和发送前重新检查主人设置。

收到申请只记录并提示管理日志，不再让申请事件自行唤醒模型决定账号操作。主人可在私聊通过 `qq_events` 查看允许范围内的申请，再使用返回的真实编号处理；跨会话申请不向普通群友或主人所在群公开。本机控制台保留可信管理地位，资料与申请的专用操作界面尚未接入。本轮没有宣称完成 DSH 沙箱、全量工具权限、内容绑定审批或业务 SQLite 迁移。

### 第三批：组件准备与内部发行包

用户确认开源项目用于个人使用，项目代码采用 MIT。第三方组件保留原许可，NapCat 按个人非商业范围从官方来源获取；没有把它或 QQ 登录文件重新声明为 MIT。

桌面快速配置新增「准备运行组件」，支持 DSH 在线准备和 QQ 官方 ZIP 下载/本地导入。固定 Node 24.22.1、DSH 0.2.1-rc.2 与 NapCat 4.18.41，使用官方摘要、固定依赖清单与 SRI 校验；拒绝越界、链接和大小写冲突等异常 ZIP。安装使用独立版本目录与原子活动记录，失败或取消保留旧版本；准备期间获取共享资源锁，停止同一数据实例后才能安装。取消与退出不受安装队列阻塞。

安装子进程不继承项目密钥、DSH 会话和用户 npm 配置，不执行依赖生命周期脚本。真实下载的 DSH 已验证版本及 ACP 初始化，未发送模型请求；这不等于全部原生工具均可用，也不是完整工具沙箱。完成后只补全未修改的默认/受管路径草稿，保存由用户执行；自定义 DSH 的隐式登录目录不会被安装结果改变。

受管 NapCat 使用官方包内自己的 Node 22.11.0 与 QQ 运行文件，不再要求系统 QQ 目录；应用桥接与 DSH 使用 Node 24，避免错误复用低于 SQLite 最低版本的运行库。QQ 配置保留在稳定数据目录，首次 WebUI 绑定本机并生成随机令牌。真实 QQ、扫码、OneBot 自动安全配置与登录状态仍待验证。

新增 `npm run package:dir`，按白名单复制业务、桌面和公开模板，以隔离 npm 环境安装锁定生产依赖，生成包含 Node 的内部目录及可选 ZIP。输出仅限 `release` 的直接子目录且不覆盖已有包。包内不包含个人环境、工作区、聊天或登录文件；首次使用仍需联网准备组件并提供自己的模型凭据。此发行布局保留现有 `dist/` 与 `desktop/` 相对结构，以复用已有启动契约；原方案中的逻辑应用层未单独增加 `app/` 包装层。详见[组件与打包说明](components-and-packaging.md)。

本轮回归还发现了同时抢锁和 Windows 临时文件占用问题：SQLite 忙碌仅做短暂有界退避，持续占用仍拒绝；社交 JSON 原子替换增加有上限的 Windows 重试，并验证 500 ms 读句柄占用后可以恢复。

### 数据资源锁

使用 Node 自带 SQLite 在独立侧文件上持有 `BEGIN EXCLUSIVE` 事务，借助操作系统文件锁实现互斥。业务数据仍使用当前 JSON 格式，这不是业务存储迁移。无需另起原生锁进程，也不依赖 PID 过期或主动删除“旧锁”。

- 统一规范化绝对路径、Windows 大小写及目录联接；同时保护显式覆盖的共享文件。
- 按统一顺序取得全部资源；任一资源冲突就释放本次已取得的锁。
- 进程退出后由系统释放锁；侧文件保留，不影响下一次启动。
- 硬链接、文件符号链接及失效链接明确拒绝，避免 JSON 原子替换改变锁身份；目录联接/有效目录链接支持。当前支持本机文件系统，不承诺网络盘锁语义。
- 备份与恢复不需要携带 `*.qqbot-lock.sqlite`；程序运行时不要删除或替换这些文件。

首次切换到新版本前必须停止全部旧桥接。旧版本不获取资源锁，因此新旧版本混跑不能获得跨版本互斥保护。原始 JSON 文件和个人配置不会因为建立锁而迁移或重置。

### 消息准入与聚合

消息结构校验及管理员审批先于普通归档处理。普通消息在任何异步存档操作前预留条数与字节预算，超过容量就拒绝，不进入归档写入链和模型请求。

默认全局 500 条、每会话 50 条、载荷总计 16 MiB；普通旁聊只能使用约 80% 的条数和字节容量，其余留给私聊和直接 @/称呼/引用/追问。极小容量至少保留一个普通准入位置。管理员的有效审批回复不消耗这份预算。

每次聚合另限 64 KiB UTF-8 内容。聚合期间保留原消息预算，不能因为早期等待者结束就把仍留在聚合对象中的内容排除在计数之外。聚合完成、拒绝、取消和退出都会释放预算。

单个 OneBot 消息最多 128 个消息段、文字合计 32 KiB UTF-8、事件载荷 256 KiB。通知/申请元数据最多 16 KiB，同样参与入站容量控制，不能绕过普通消息预算；申请和撤回事件可使用预留容量，避免普通通知阻塞来源撤销。超限消息拒绝处理，不截断原话后继续请求模型。WebSocket 帧原有上限继续保留。

忙碌提示继续按会话限频，同时限制在途发送数量；入站拒绝日志限频，计数仍逐条累计。运行状态新增待处理入站条数、字节及拒绝数量。
