### 阶段 B：建立独立部署分支

阶段 A 收尾后，从已提交的本地检查点建立 `codex/linux-remote-console` 分支。保留本地收尾分支及 Windows 候选，服务器适配在新分支推进。

首先盘点 Windows 专属路径、进程管理、凭据、QQ 启动、组件安装、维护和本地文件操作，形成逐项迁移清单；保持聊天、权限、记忆、任务、媒体及维护功能的既有行为。

**完成标准：** 明确每项功能在服务器和本地控制台的归属、传输方式和验收用例；不以“能启动 Node”代替部署适配完成。

### 阶段 C：Linux 运行组件与服务

1. 固定 Linux x64 Node、DSH、NapCat 及对应 QQ 组件版本、来源、摘要和许可；补齐无桌面运行依赖。
2. 适配程序/数据目录、权限、进程树与停止恢复；补齐 Linux 媒体清理、备份恢复及诊断路径。
3. 提供服务安装、启动、停止、日志与开机恢复流程，退出 SSH 或关闭本地控制台后机器人继续运行。
4. 补齐服务器安装、更新、备份及失败恢复说明，明确与 Windows 安装器的边界。

**完成标准：** 在新 Ubuntu 虚拟机完成从空实例准备到服务运行、重启恢复及维护的闭环，生产组件来源可核对。

### 阶段 D：本地桌面控制台远程连接

1. 保留现有 Windows 桌面界面，增加远程连接配置与清晰的连接状态。
2. 优先通过 SSH 密钥和固定主机身份连接，管理服务及 QQ 接口保持私有访问。
3. 将启停、配置、状态、日志、QQ 扫码、模型测试、活动和知识管理接入同一远程管理通道。
4. 为组件导入、备份下载/上传、诊断导出、媒体及工作区文件操作处理本地与服务器路径差异。
5. 完成断线、重连、重复控制台连接、操作取消及服务端继续运行的行为定义与测试。

**完成标准：** 按现有功能清单逐项核对，不能只交付远程启停，也不能用网页替代本地桌面要求。

### 阶段 E：虚拟机联调和交付

在 Ubuntu 虚拟机验证安装、连接、扫码就绪、服务重启、掉线重连、配置与文件传输、备份恢复、升级失败处理和数据保留。真实 QQ/模型验收使用独立测试实例安排，避免影响现有账号会话。

**完成标准：** 留存 Linux 环境、组件清单、代码版本和实际通过/失败记录；列明未验证能力及使用说明，再形成部署分支交付检查点。
