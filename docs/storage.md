# 本地业务存储

社交消息、联系人、记忆、表情记录、提醒、动作、轮次、会话覆盖、兴趣、想法、学习状态及每日额度使用 SQLite。桥接和离线管理使用同一仓储；会话映射和群上下文目前仍使用原格式。

## 旧数据迁移

首次读取旧社交文件时，在其旁边创建 `<原路径>.sqlite`，自定义 `BOT_SOCIAL_STORE` 路径同样适用。迁移支持 v1/v2 的全部已知业务字段，保留原文，并生成带原文摘要的 `.pre-sqlite-<摘要>.bak`。数据库先写入独立暂存文件，逐条核对规范化摘要并检查完整性，所有连接关闭后才发布到正式路径。不会覆盖已经存在的正式数据库。

验证失败、中断、磁盘空间不足、重复编号或源文件发生变化时，保留原文件和备份，拒绝开放半成品。重新启动可从原文重新迁移；强制退出产生的暂存文件不能直接充当正式数据库。旧文件在迁移后被另一个程序修改时，新程序拒绝覆盖或合并，需先保留两份数据并核对。

数据库中的 `running` 提醒、动作、学习或自主任务在重新打开时转为结果待核对，不自动重复提交外部操作。旧程序不能读取迁移后新增的数据库记录，不能仅切回旧 EXE 就当作完整回退。完整数据维护、恢复及程序配对回退入口仍在开发。

## 离线检查与导出

先停止使用该数据的机器人；维护入口会检查共用资源锁，拒绝与运行实例争用。命令读取选定数据目录的路径配置，不需要填写内部数据库文件名。

```powershell
node scripts/storage.mjs status --data-dir "D:\小鲸数据"
node scripts/storage.mjs migrate --data-dir "D:\小鲸数据"
node scripts/storage.mjs verify --data-dir "D:\小鲸数据"
node scripts/storage.mjs export --data-dir "D:\小鲸数据" --output "D:\私有备份\社交记录.json"
```

`status` 显示是否已迁移，`migrate` 执行安全迁移，`verify` 检查数据库及旧来源是否变化。`export` 在一个数据库读取事务中逐条写出全部社交数据，完成并落盘后才发布文件，拒绝覆盖已有目标；不会把全部消息通过管理 IPC 返回。导出保留原始动作状态，不执行启动恢复，也不修改当前数据库。

导出包含聊天正文等私有内容，适合本人保管和核对两份数据；不属于可分享诊断包。即使旧 JSON 被另一个程序修改，也可导出数据库供核对。该工具尚不提供把旧备份直接覆盖当前数据的操作。

## 运行边界

`src/storage/social-repository.ts` 区分业务元数据视图与可等待的归档查询。消息历史留在数据库工作线程；新增消息只插入对应条目，事务更新联系人并按保留设置清理。会话、时间、编号及提醒状态有索引。其他业务状态按访问字段复制、校验并比较条目，只提交实际变化；清理数组头部时保留其余条目的位置，不重写所有正文。JSON 仓储保留为兼容参考和测试实现。

数据库工作线程使用固定参数化操作，不接受模型 SQL。最多排队 64 个请求、合计 8 MiB；单请求最多 2 MiB，单响应最多 16 MiB。超限明确失败，不扩展无界队列。元数据达到支持容量前原子拒绝增长，已提交数据仍可读取和整理；旧文件单条超过 1 MiB 或文件超过 256 MiB 时不自动迁移。社交消息继续采用原有 5 万条总上限及每会话保留设置。

写入使用 WAL、`synchronous=FULL` 和数据库事务，返回成功前等待提交。修订号冲突会拒绝第二个写入者；入口仍持有独立资源锁，保护旧路径、数据库及共享媒体。工作线程退出或超时时拒绝所有未完成请求，并停止继续使用失效连接；调用不会被自动重放。进程监督器负责按错误类型恢复实例。

SQLite 的同步 API 运行在 Worker 中，依据 [Node SQLite 官方文档](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。一致性备份原语在同一工作线程使用 `VACUUM INTO`，拒绝覆盖目标；不能用文件复制替代正在写入时的备份。

## 每日额度

旧每日额度文件迁移到 `<原额度路径>.sqlite`，支持独立 `BOT_USAGE_STORE`，不因更换社交文件而重置共享额度。原文及摘要备份保留，分批导入后核对全部键值再激活；来源变化或格式无效时拒绝继续。社交与额度数据库记录各自类型，路径误配不会将另一类数据当作空记录使用。数据库 schema 1 通过事务升级到 schema 2，既有社交内容保持不变。

动作总额度、群聊额度和专用额度在一个事务中预扣，任一不足则整笔回滚。唯一预扣编号绑定日期与实际额度内容，同一编号重试不再次扣除，换内容会被拒绝；应用不会自动重放失败请求。提交后才允许调用“已预扣”回调，远端失败、未知结果或宿主退出均不自动退回。此处记录预扣次数，不推算模型计费用量或金额。

上海日期分别保存，时钟回退不能抹掉旧日期的用量。SQL 继续是额度判断依据，本地缓存只供展示和提前判断；额度拒绝后刷新当前日期缓存。入口及额度数据库均有排队上限，超过记录容量时拒绝新增，不伪装成功。额度类别最多 2 万个，预扣记录总量最多 20 万条，成功跨日预扣时按 31 天保留策略清理更早记录。

## 当前验证

### 模型与能力请求

schema 2 原子升级到 schema 3，增加服务请求登记。每次实际模型请求（含重试与压缩）、独立媒体、后台学习和原生联网，在外部提交前将全局、用户/会话、后台及专用额度一起预扣。唯一请求编号不能再次提交外部服务；重启后的未结算请求保留为未知，不退款或自动重放。学习预算拒绝时不推进资料整理游标，媒体请求与发起它的聊天轮次共享每轮上限。

登记区分请求种类和前台/后台来源，只保存会话、用户、模型、上限及服务上报用量，不写入请求正文或凭据。缺失用量保持未知，原生联网与未上报用量的语音请求不伪装成零 Token；不估算价格。桌面“额度与节奏”可调整请求次数、并发、速率、材料和输出上限，并查看当天总量及已知/未知用量。

真实 DSH 请求钩子在进入适配器前执行预算，工具守卫使 QQ 与原生搜索/读取共享每轮工具上限；单次模型输出同时限制 Token 参数与返回内容长度。固定组件的压缩上限在连接时配置，降低输出设置后若旧压缩请求超过新上限，将拒绝提交；重新连接模型可应用新的压缩上限。独立能力在排队后再次校验开关、范围和取消信号。

验证使用真实 SQLite、独立媒体/学习夹具和固定 DSH 组件的实际模型及工具注册器。包括预算拒绝不进入适配器、压缩与重试计次、QQ/联网共享工具数、超大输出取消、能力关闭后拒绝、已上报值与未知结果、学习拒绝不推进游标，以及重启保守恢复。未调用付费模型或真实 QQ，不据此声称完成线上计费或长期运行验收。

全量隔离回归 337 项通过，另有真实 Windows 原生窗口与独立数据目录冒烟。数据库验证覆盖索引计划、复合消息编号、事务回滚、两个真实 Worker 的写入冲突、Worker 退出/超时/背压、过新或损坏文件、迁移完整性与失败保留，以及一致性备份。触发器验证替换最早轮次时只删除一条、插入一条，不更新其余 499 条正文。额度验证另覆盖真实 Worker 并发、整笔回滚、预扣编号、上海跨日、时钟回退及提交后宿主退出。

短串行诊断使用固定 20 会话、每档 3 轮，每轮预热后记录 100 次，包含 Worker RSS。原始结果见[短基准](benchmarks/store-sqlite-short-2026-10-27.json)：

| 初始存档 | 归档 P95 | Worker P95 | 查询 100 条 P95 | RSS |
| --- | --- | --- | --- | --- |
| 1 万条 | 1.80–2.01 ms | 1.63–1.74 ms | 3.66–4.04 ms | 128–132 MiB |
| 5 万条 | 1.96–2.27 ms | 1.77–2.01 ms | 4.02–4.10 ms | 196–197 MiB |

5 万条首次迁移约 6.9–7.1 秒。该结果是短诊断，不能替代 30 分钟混合负载、10 万条容量行为、干净机器、系统断电或 72 小时/7 日验收。复现命令：

```powershell
npm run build
node --expose-gc scripts/benchmark-sqlite.mjs --output <报告路径>
```
