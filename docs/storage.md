# 本地业务存储

社交消息、联系人、记忆、表情记录、提醒、动作、轮次、会话覆盖、兴趣、想法、学习状态、每日额度、会话映射和群上下文使用 SQLite。桥接和离线管理使用共同的社交及额度仓储。

## 旧数据迁移

首次读取旧社交文件时，在其旁边创建 `<原路径>.sqlite`，自定义 `BOT_SOCIAL_STORE` 路径同样适用。迁移支持 v1/v2 的全部已知业务字段，保留原文，并生成带原文摘要的 `.pre-sqlite-<摘要>.bak`。数据库先写入独立暂存文件，逐条核对规范化摘要并检查完整性，所有连接关闭后才发布到正式路径。不会覆盖已经存在的正式数据库。

验证失败、中断、磁盘空间不足、重复编号或源文件发生变化时，保留原文件和备份，拒绝开放半成品。重新启动可从原文重新迁移；强制退出产生的暂存文件不能直接充当正式数据库。旧文件在迁移后被另一个程序修改时，新程序拒绝覆盖或合并，需先保留两份数据并核对。

数据库中的 `running` 提醒、动作、学习或自主任务在重新打开时转为结果待核对，不自动重复提交外部操作。旧程序不能读取迁移后新增的数据库记录，不能仅切回旧 EXE 就当作完整回退。完整数据维护、恢复及程序配对回退入口仍在开发。

自主任务按状态/到期索引读取最多二百个候选，再以事务取得唯一领取凭证。完成更新同时核对当前运行状态与凭证，取消、推迟或换代后的旧结果不能覆盖当前记录，也不能追加失效的完成摘要。领取后中断保留凭证并转为待核对。schema 6 只新增到期索引，旧业务数据和状态保留。

自主机会按种类及会话轮转，位置随业务状态持久保存；模型队列接纳后才预扣判断额度，忙碌退回不计判断次数。实际 QQ 副作用仍通过独立动作账本与总额/专用额度检查。上述行为不替代学习任务领取、睡眠恢复或系统时钟变化的完整验收。

自主扫描和最小判断间隔使用单调时钟，重启时从持久时间初始化；已观测的间隔不会因墙钟跳变缩短或延长。未来的持久扫描/判断时间最多等待一个对应间隔后重查，原决策时间保留。定时提醒的约定到期时间仍按墙钟判断；学习游标及其它冷却的时钟边界另行完善。

schema 7 为资料整理增加会话/状态索引。学习先领取准备记录，预算和材料检查通过后，将运行状态与游标一起提交，再调用分析。准备记录尚不代表提交模型：准备中断恢复为明确失败，可重新安排；运行中断则保留游标与未知结果，自动调度不重提同批材料。预算拒绝不推进游标或留下未提交的准备记录。晚到提案必须匹配当前运行阶段及领取凭证，且记忆原文修订保持一致；标点和空白改变也会使旧提案失效。

学习材料保留完整选中消息和记忆，超出共同请求大小预算时直接拒绝，避免截断否定、转述或解释。模型与 QQ 工具仍未挂载到学习分析通道。未知分析可由本机所有者明确发起新的手动整理；该操作按新的服务请求计次。

## 媒体大小索引与保存恢复

schema 8 在已有额度数据库内增加媒体文件索引，不新增第五个数据库。首次使用与显式核对分批扫描目录；正常保存使用事务计数和容量预留，不再逐次遍历目录。默认总额度 512 MiB，可用 `BOT_MEDIA_MAX_BYTES` 调整；最多索引二万个普通文件，单次保存最多五千万字节，待保存最多八项、合计 128 MiB。入口复制已接纳的材料，超限先拒绝，不无界积压。

保存先预留容量，排他创建临时文件并登记实际设备/文件标识，写入和同步后以不覆盖已有路径的方式发布，再确认索引。相同摘要文件重新核对实际内容，不静默覆盖损坏或被替换的文件。发布前失败撤销已确认移除的预留；发布后确认丢失停止继续保存，交由现有监督器恢复。磁盘写满及存储 I/O 故障同样停止后续保存。

重启把未确认预留标为待核对；扫描只删除名称、持有凭证和实际文件标识均匹配的旧临时文件，保留已发布文件、用户文件及被替换的临时路径。核对只整理索引，不自动删除普通缓存。当前已完成大小索引与保存恢复基础，收藏/任务/未知动作的引用保护、按保留期清理以及视频临时资源完整预算仍继续开发。

## 离线检查与导出

先停止使用该数据的机器人；维护入口会检查共用资源锁，拒绝与运行实例争用。命令读取选定数据目录的路径配置，不需要填写内部数据库文件名。

```powershell
node scripts/storage.mjs status --data-dir "D:\小鲸数据"
node scripts/storage.mjs migrate --data-dir "D:\小鲸数据"
node scripts/storage.mjs verify --data-dir "D:\小鲸数据"
node scripts/storage.mjs export --data-dir "D:\小鲸数据" --output "D:\私有备份\社交记录.json"
```

`status` 显示是否已迁移，`migrate` 执行安全迁移，`verify` 检查数据库及旧来源是否变化。`export` 在一个数据库读取事务中逐条写出全部社交数据，完成并落盘后才发布文件，拒绝覆盖已有目标；不会把全部消息通过管理 IPC 返回。导出保留原始动作状态，不执行启动恢复，也不修改当前数据库。

导出包含聊天正文等私有内容，适合本人保管和核对两份数据；不属于可分享诊断包。即使旧 JSON 被另一个程序修改，也可导出数据库供核对。该工具尚不提供把旧备份直接覆盖当前数据的操作。

## 运行边界

`src/storage/social-repository.ts` 区分业务元数据视图与可等待的归档查询。消息历史留在数据库工作线程；新增消息只插入对应条目，事务更新联系人并按保留设置清理。会话、时间、编号及提醒状态有索引。其他业务状态按访问字段复制、校验并比较条目，只提交实际变化；清理数组头部时保留其余条目的位置，不重写所有正文。JSON 仓储保留为兼容参考和测试实现。

数据库工作线程使用固定参数化操作，不接受模型 SQL。最多排队 64 个请求、合计 8 MiB；单请求最多 2 MiB，单响应最多 16 MiB。超限明确失败，不扩展无界队列。元数据达到支持容量前原子拒绝增长，已提交数据仍可读取和整理；旧文件单条超过 1 MiB 或文件超过 256 MiB 时不自动迁移。社交消息继续采用原有 5 万条总上限及每会话保留设置。

写入使用 WAL、`synchronous=FULL` 和数据库事务，返回成功前等待提交。修订号冲突会拒绝第二个写入者；入口仍持有独立资源锁，保护旧路径、数据库及共享媒体。工作线程退出或超时时拒绝所有未完成请求，并停止继续使用失效连接；调用不会被自动重放。进程监督器负责按错误类型恢复实例。

SQLite 的同步 API 运行在 Worker 中，依据 [Node SQLite 官方文档](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。一致性备份原语在同一工作线程使用 `VACUUM INTO`，拒绝覆盖目标；不能用文件复制替代正在写入时的备份。

## 会话映射与群上下文

会话映射和群上下文分别迁入 `<原路径>.sqlite`，保留 `SESSION_STORE` 与 `BOT_GROUP_CONTEXT_STORE` 的独立绝对路径及资源锁。旧文件保持原样，另生成摘要命名的原文备份；暂存库分批导入并逐条校验摘要及完整性，关闭后才不覆盖地激活。损坏、超容量、来源变化、类型误配及中断均不激活不完整数据。四类数据库各自记录类型，不能把另一类文件当作空记录打开。

会话映射按键增删，保留更新时间、工具策略和会话代次，映射提交成功后才向模型开放该会话。群上下文按单条消息写入，保持账号/群隔离、序号、追问目标和回答引用；队列中的问题不会读到之后的用户发言。每群保留八十条、最近一天、最多一百群；淘汰记录与群顺序一起事务提交，不重写其余消息正文。批量清理在完整的逻辑修改之间分批，中断后仍可验证和恢复。

运行缓存最多一万条会话映射及八千条群上下文。单次原子写入最多 256 条、1 MiB，待写批次最多 64 个、8 MiB；每个分库还受共同的业务元数据容量限制。持续写入期间的变动全部排空后才结束 `flush`，修订冲突、Worker 失效或写入失败停止使用仓储并进入监督恢复。

活跃模型会话独立管理，默认最多 128 个、空闲三十分钟后释放，可在桌面“额度与节奏”调整。按单调时钟记录最近使用，活动或排队会话受保护；创建中的名额也计入上限，换代不突破上限。淘汰必须等待 DSH 确认 `session/close`，再释放本地更新流及名额；历史映射保留，下次按需恢复并重新生成工具凭据。释放结果不明确时停止继续创建，并通过监督器重连模型。正常停止由既有进程树保护回收整个受管模型进程。

组件激活前还验证真实隔离 ACP 会话创建、关闭、磁盘恢复和再次关闭，运行时要求组件声明关闭能力；这些探针不发送模型提示词。会话创建、恢复、模型选择、换代、取消后丢弃及重置集中在 `ConversationService`，桥接保留业务历史和可信身份的组装。

专项以真实进程退出验证首次迁移不发布半成品、多批群淘汰中断后没有孤立记录；数据库触发器验证八十条群记录新增一条只插入一条、删除一条，不更新其余七十九条正文。旧 JSON 类继续保留作参考实现，正常桥接不再写回这些旧文件。

## 每日额度

旧每日额度文件迁移到 `<原额度路径>.sqlite`，支持独立 `BOT_USAGE_STORE`，不因更换社交文件而重置共享额度。原文及摘要备份保留，分批导入后核对全部键值再激活；来源变化或格式无效时拒绝继续。社交与额度数据库记录各自类型，路径误配不会将另一类数据当作空记录使用。数据库 schema 1 通过事务升级到 schema 2，既有社交内容保持不变。

动作总额度、群聊额度和专用额度在一个事务中预扣，任一不足则整笔回滚。唯一预扣编号绑定日期与实际额度内容，同一编号重试不再次扣除，换内容会被拒绝；应用不会自动重放失败请求。提交后才允许调用“已预扣”回调，远端失败、未知结果或宿主退出均不自动退回。此处记录预扣次数，不推算模型计费用量或金额。

上海日期分别保存，时钟回退不能抹掉旧日期的用量。SQL 继续是额度判断依据，本地缓存只供展示和提前判断；额度拒绝后刷新当前日期缓存。入口及额度数据库均有排队上限，超过记录容量时拒绝新增，不伪装成功。额度类别最多 2 万个，预扣记录总量最多 20 万条，成功跨日预扣时按 31 天保留策略清理更早记录。

## 当前验证

### 入站身份与提醒领取

schema 3 原子升级到 schema 4，独立保存入站身份去重记录；旧社交归档在导入或升级时保守地标记为已接收。新消息的去重身份与归档同事务提交，业务只有在首次准入成功后才继续；保留期清理、每会话裁剪及进程重启不会因归档消息消失就重复触发。运行后的历史补拉只归档，不提前消费尚未实际到达的新消息身份。去重记录最多二十万条，按接收时间保留三十一天；已明确超过三十一天的上游历史帧不唤醒模型。记录表示身份已准入，不承诺处理已完成，崩溃后不自动重放未完成轮次。

提醒按状态、到期及重试时间索引查询，每次最多十条。领取通过事务校验状态和时间，写入本次实例及唯一凭证；完成、失败或延后必须匹配当前凭证，旧执行者不能覆盖新一轮或已恢复为未知的状态。取消先提交时不能再领取。领取后中断保留待核对，不自动补发。

周期提醒错过一整段周期时跳过积压，安排下一次；一次性提醒迟到超过二十四小时停止补发并留下原因。正常到期只发送一次，外部提交后结果不明仍保留未知，不自动返还额度。这些规则不把协议接口描述为严格“恰好一次”；完整的逻辑外部动作登记及维护核对仍需后续工作。

### 外部动作事务基础

schema 5 增加独立的逻辑动作和实际提交步骤，位于每日额度分库。动作绑定可信轮次、账号、用户、目标和完整参数摘要，执行实例及唯一编号不能替换。总额、专用额度和动作“已预扣”状态在同一事务提交；只有预扣后才能登记实际提交步骤，最多十六步。相同编号读取已确认返回值，未确认步骤不自动重放；同轮未知的实际提交也不能通过更换工具或临时引用编号重发。新明确轮次的合法相同内容保留为不同动作。

执行器合并同一编号的并发调用，提交前及等待预扣后重新检查授权和取消。真实消息响应缺少有效编号时保留未知，未开始外部提交的失败可以明确标记失败。开始、预扣或提交阶段在宿主退出后均保守恢复为未知，额度不退回；已确认结果不因管理摘要写入失败被抹掉。

记录最多二十万条、内容总量最多 128 MiB，单个动作材料最多 256 KiB、提交步骤结果最多 64 KiB、最终结果最多 512 KiB。只自动整理超过三十一天的已完成或明确失败记录，未知记录保留待核对。管理列表每页最多一百条，不返回参数正文；私有数据库备份必须包含这些协调记录，普通 JSON 社交导出不能替代完整恢复备份。

QQ 工具、普通回复/失败提示、提醒发送、空间发布/评论、授权/忙碌通知及本机手动收藏/移除均接入动作执行器。私有 MCP 传输编号与可信轮次、账号和参数一起绑定，模型参数不能自报执行身份；编号来自本机 MCP SDK 请求和独立传输实例，不声称它是模型服务的原始调用编号。同轮相同内容在传输重连后复用已确认结果，不再次预扣；改变工具或临时阅读编号时仍按真实协议参数检查，未知或正在提交的同轮相同效果不能再次进入远端。跨工具复用已确认步骤时，新的逻辑尝试保留已预扣额度。

实际 QQ 写入在提交边界再读取登录账号，账号变化时停止业务并提示使用独立数据目录，不自动恢复到新账号。协议动作按工具逐项登记，未知协议动作或缺少执行上下文的写入拒绝。授权、授权结果及忙碌通知共享每日四十次默认专用额度，也占用 QQ 动作总量；可在桌面调整。确认通知只发当前主人，忙碌提示仍检查会话开关及联系范围。空间评论以真实作者、动态和评论编号登记，接口不返回有效评论编号时保留待核对。

上述验证使用实际 SQLite、两个 Worker、宿主强制退出、本机 HTTP 响应丢失以及完整隔离桥接；没有调用付费模型或真实 QQ。自主/学习任务的领取和公平调度、完整私有备份及正式发行验收仍继续实施。

### 模型与能力请求

schema 2 原子升级到 schema 3，增加服务请求登记。每次实际模型请求（含重试与压缩）、独立媒体、后台学习和原生联网，在外部提交前将全局、用户/会话、后台及专用额度一起预扣。唯一请求编号不能再次提交外部服务；重启后的未结算请求保留为未知，不退款或自动重放。学习预算拒绝时不推进资料整理游标，媒体请求与发起它的聊天轮次共享每轮上限。

登记区分请求种类和前台/后台来源，只保存会话、用户、模型、上限及服务上报用量，不写入请求正文或凭据。缺失用量保持未知，原生联网与未上报用量的语音请求不伪装成零 Token；不估算价格。桌面“额度与节奏”可调整请求次数、并发、速率、材料和输出上限，并查看当天总量及已知/未知用量。

真实 DSH 请求钩子在进入适配器前执行预算，工具守卫使 QQ 与原生搜索/读取共享每轮工具上限；单次模型输出同时限制 Token 参数与返回内容长度。固定组件的压缩上限在连接时配置，降低输出设置后若旧压缩请求超过新上限，将拒绝提交；重新连接模型可应用新的压缩上限。独立能力在排队后再次校验开关、范围和取消信号。

验证使用真实 SQLite、独立媒体/学习夹具和固定 DSH 组件的实际模型及工具注册器。包括预算拒绝不进入适配器、压缩与重试计次、QQ/联网共享工具数、超大输出取消、能力关闭后拒绝、已上报值与未知结果、学习拒绝不推进游标，以及重启保守恢复。未调用付费模型或真实 QQ，不据此声称完成线上计费或长期运行验收。
