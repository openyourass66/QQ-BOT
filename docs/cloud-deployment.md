# 云服务器部署流程

目标是单个 Linux x64 服务器运行机器人，主人通过电脑或手机浏览器管理；服务器不需要桌面。首批走 SSH 隧道，不要求域名。完整云端组件和系统服务仍在开发，以下区分最终流程与已能预览的控制台，不能将 Windows 验收替代 Linux 验收。

## 最终交付流程

1. 准备可通过 SSH 登录的 Linux x64 服务器和普通服务账户，选择独立的可写数据目录。
2. 上传并解压云端发行包。程序、运行环境和用户数据分离；升级替换程序，保留数据。
3. 初始化网页主人账号，通过隧道打开控制台，设置独立管理口令。
4. 在向导准备 Linux 模型运行器与 QQ 接入组件，填写自己的模型凭据，完成连接测试和 QQ 扫码。已有 OneBot 可选择外部接入。
5. 设置主人 QQ、允许聊天的好友和群。先做基础聊天，再按需开启自主活动与其它能力。
6. 启动机器人，分别检查 QQ 登录、消息通道与模型，完成一轮真实私聊。
7. 安装系统服务，验证退出 SSH、重启服务器后恢复运行，并设置备份、日志保留及升级恢复。

第 4、7 步的 Linux 完整自动流程尚未交付。当前 Windows ZIP 含 Windows Node 和原生文件，不能放到 Linux 当作云端包运行。

## 现在可以预览的网页控制台

已有源码可在满足项目 Node 版本要求的环境编译。以下命令以已进入项目目录为前提，使用独立数据目录；已在 Windows 验证，Linux 真实结果待记录。

```sh
npm ci --registry=https://registry.npmjs.org
npm run build
npm run web:build
npm run server:init -- --data-dir "$HOME/.local/share/WhaleWorkbench-server"
npm run server -- --data-dir "$HOME/.local/share/WhaleWorkbench-server"
```

使用与固定组件一致的 Node 24.22.1 可减少版本差异。初始化会打印 15 分钟有效的一次性认领码。管理服务当前在终端前台运行；终端进程结束会关闭此管理服务。这里初始化的是网页身份，不是 QQ 登录或模型凭据。

在自己电脑另开终端连接：

```sh
ssh -N -L 18380:127.0.0.1:18380 用户名@服务器地址
```

浏览器打开 `http://127.0.0.1:18380`，用认领码设置至少 15 个字符的管理口令。网页可查看状态、编辑允许的连接字段、更新密钥，并管理本实例的启停任务。只启动网页不会让机器人自动具备 QQ 和模型运行环境。

Linux 当前需要预先配置可用的 DSH 与外部 OneBot，网页暂不提供 Linux 受管组件安装。外部 OneBot 使用 `BOT_ONEBOT_MODE=external`，分别配置 HTTP、正向 WebSocket 及令牌；主人和联系范围须完成本机配置。不能复用 Windows 的 `.cmd`、DLL 或已有包中路径。

只需通过 SSH 访问，不必向公网开放 18380、OneBot 或 QQ WebUI。公网域名、HTTPS 和手机直接访问属于后续模式，当前不要把回环 HTTP 控制台直接映射到公网。

数据目录包含配置、模型及 QQ 登录、聊天和管理凭据，不能把整个目录作为公开附件。凭据恢复、当前接口和限制见[控制台使用说明](cloud-console.md)。
