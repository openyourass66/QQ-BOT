# 程序目录、数据目录与启动入口

已接入桌面、命令行和本机 NapCat 启动流程，并提供[组件准备及内部发行目录构建](components-and-packaging.md)。正式安装升级、旧数据迁移向导仍在开发，当前源码使用方式继续有效。

## 目录选择

| 运行方式 | 默认数据目录 | 启用方式 |
| --- | --- | --- |
| 源码 | 项目目录 | 程序目录没有发行清单 |
| Windows 发行布局 | `%LOCALAPPDATA%/WhaleWorkbench` | 程序目录具有有效的发行清单 |
| 便携 | 程序目录的 `user-data/` | 启动时指定 `--portable` |
| 自定义 | 指定的目录 | `--data-dir 路径`，或系统环境变量 `BOT_DATA_DIR` |

自定义目录参数优先于系统环境变量；自定义目录与 `--portable` 互斥。相对的自定义目录以调用者启动时的工作目录为基准，解析后传递绝对路径。源码默认路径以程序目录为准，不受快捷方式工作目录影响。目录联接会归一，桌面单实例标识按数据目录建立；底层数据资源锁继续保护独立覆盖的共享文件。

发行布局以程序目录的 `release-manifest.json` 识别，格式为：

```json
{"formatVersion":1,"appId":"whale-workbench","version":"0.2.0"}
```

这是后续打包流程使用的布局契约。不要在正在使用的源码目录手工添加清单；那会切换默认数据目录。清单损坏或版本不兼容时明确停止，不回退成另一种模式。Windows 发行版找不到用户目录时要求显式选择数据目录。

## 文件归属

程序目录放置 EXE、`desktop/` 静态资源与后台代码、`dist/`、生产依赖、`scripts/`、`templates/` 和 `.env.example`。发行版桌面必须有 `runtime/node.exe`，缺失就提示重新解压完整程序，不会依赖系统 Node 启动。源码版仍可使用系统 Node。

数据目录保存：

- `.env`、`bot.config.json`、`bot-workspace/` 与其中的人设、记忆、人设库；
- `data/` 内的会话、群上下文、每日额度、社交存档、媒体与桌面日志；
- `data/desktop/setup-complete` 首次配置完成标记；
- `napcat/` 中本机组件与 `node-runtime/` 的可写运行文件。

首次启动只补齐缺失的 `.env` 和默认人设，保留已有文件。数据目录不可写时显示错误及 `--data-dir` 处理方法，不静默换目录。界面主题与资源始终从程序目录读取；打开日志使用数据目录。原生界面测试的截图和结果文件属于测试输出，仍写入测试程序目录。

`.env` 内的相对路径统一以数据目录解析，包括设置、工作区、存档、DSH 启动文件和数据目录、QQ 与 NapCat 路径。`dsh.cmd` 这类不带目录的命令仍通过 PATH 查找；`tools/dsh.cmd` 会先转换为绝对路径，避免切换到机器人工作区后找错入口。绝对路径保持有效。

`BOT_DATA_DIR` 是读取 `.env` 之前使用的启动选项，只能放在系统环境变量中，或改用 `--data-dir`。高级配置编辑器会拒绝把它保存进 `.env`。桌面诊断、配置编辑器与启动的子进程均以保存文件优先；命令行沿用 Node 的环境变量优先规则。

DSH 默认个人配置目录及账号登录态的隔离尚属 S02 范围，本轮保留现有默认行为，不自动复制或重置 DSH 凭据。

## 启动示例

源码继续执行原来的 `npm run setup`、`npm start`、`npm run desktop`。需要独立数据时：

```powershell
npm run setup -- --data-dir 'E:\机器人数据'
npm start -- --data-dir 'E:\机器人数据'
npm run napcat -- --data-dir 'E:\机器人数据'
```

桌面 EXE 支持：

```powershell
.\QQ-BOT.exe --data-dir 'E:\机器人数据'
.\QQ-BOT.exe --portable
```

`node scripts/app-paths.mjs` 只输出路径解析结果，不写入数据。`scripts/run.mjs` 在初始化并读取所选 `.env` 后才导入业务入口，支持 `bridge`、`mcp`、`napcat`、`setup`。直接执行 `node dist/bridge.js` 仍是依赖调用者工作目录和环境的开发入口。

## 现有用户升级

源码运行不会自动搬动现有数据。当前升级检出目录与正在使用的原项目保持隔离；需要使用原数据时，先停止全部旧桥接，再显式指定原项目目录作为数据目录，核对工作区及各存储路径后启动。不要让旧版与新版同时写同一份数据。

自定义绝对路径不会自动搬迁。复制目录时应保留实际工作区、存档和需要的组件；跨目录导入、备份恢复与迁移校验向导仍待实施。本轮验证了临时发行布局和原生窗口的分离运行，不等同于完成干净机器安装、真实 QQ 登录或安装器验收。
